# v0.13.1 — 面板跟着会话走（多会话不再手动切靶标）

> 主题：**控制台与"当前会话"对齐**。多会话并行时（或一个会话打完换下一个单位时），
> 右侧控制台不再停留在"上一次手动选的靶标"上 —— 左侧切到哪个会话，右侧就显示那个会话的靶标。
> 知识库页签同源，默认筛到当前会话的靶标。纯 UI + 绑定记账改动，**不改事实库结构**。

## 一、面板跟随会话

以前：控制台顶部的靶标下拉是**全局**的，谁最后打开面板就显示谁的靶标 ——
多开两个会话打不同单位时，切过去看到的还是上一个单位的资产，得手动在下拉里再挑一次。

现在：靶标下拉默认由"当前会话"决定，下拉旁边常驻状态提示：

| 状态 | 含义 |
| --- | --- |
| `跟随会话`（绿） | 面板显示的正是当前会话绑定的靶标，切会话会自动跟着切 |
| `未跟随：<靶标>`（黄，可点） | 当前会话绑的是别的靶标（用户手选过），点一下切回本会话的靶标 |
| `本会话未绑靶标`（灰） | 这个会话还没开工/老会话没有绑定记录 —— 面板保持不动，不假装已绑定 |

规则说清楚：

- 会话绑过靶标（智能体 `redteam_engagement_open` / `redteam_session_bind`）→ **自动切**；
- 点开的是**子智能体的会话** → 沿 `parentSession` 解析到根会话再查绑定（子智能体继承父会话靶标）；
- 会话没绑过，但**会话标题**能认出单位（标题 = 工作目录名 = 单位名，升级前建的会话就是这种）
  → 按标题反查命中，标签显示 `跟随会话 · 按标题`；
- 会话没绑过、标题也认不出 → 回落"最后一次绑定的靶标"（本设备记的），面板**不清空**；
- 用户在下拉里**手选**了别的靶标 → **本会话内**不再跟随（一次会话重渲染不会把它抢回去），
  并写回绑定表（切走再切回来仍是它）；切到别的会话即恢复跟随。

**排查"为什么不跟随"**：面板底部常驻 `会话 <id前缀> · <跟随来源>`，来源取值
`落盘绑定` / `会话标题` / `上次选择` / `默认单位` —— 一眼看出当前靶标是凭什么选出来的。

## 二、绑定表落盘

- 新增 `$DSH_HOME/redteam/sessions.json`（键 = **根会话 id**，值 = 靶标 id/名称/时间），
  由两条路径写入：智能体绑定靶标时（工具侧）、用户在面板手选靶标时（界面侧）。
- 面板经新的 `sessionBinding` / `sessionBindings` / `bindSessionEngagement` 三个 op 读它，
  不再依赖进程内状态 —— **重启 dsh web 后仍然对得上**（以前重启就丢）。
- 只留最近 200 条；指向已删靶标的条目在下一次写入时自动清理。

## 三、知识库按会话上下文筛

知识库仍是**全局共享、跨靶标复用**，但打开时默认筛到当前会话的靶标：
页签顶部标出「来源靶标 X ✕」，点一下回到全库（全库/单靶标一键切换）。
打 B 单位时第一眼看到的就该是 B 单位攒下的武器，而不是 200 条混在一起。

## 四、升级说明

- 客户端 UI 会自动热重载；**host 侧新增了 op，需要重启一次 `dsh web`**（`node scripts/deploy-local.mjs --restart`）。
- 未重启时行为与升级前完全一致（面板问不到绑定 → 走原来的全局指针逻辑），不会白屏也不会报错。
- **改完记得刷新浏览器**：客户端 bundle 是页面加载时取的，刷新后才带新逻辑。
